## 予測曲線が実線とほぼ重なるチャート

「LSTM で株価を予測してみた。予測曲線が実際の株価とほぼ一致した」——この型の記事は、日本語圏で何年も量産され続けています。Qiita で「LSTM 株価予測」と検索すれば、似た構成のコードと、実線に吸い付くような予測曲線のチャートが何本も見つかります。

今回、その代表格といえる 1 本（172 LGTM、コード全掲載、レーザーテック 6920.T を対象）を検証しました。ただし普通の追試ではなく、**結果を見る前に「何が出たら主張を棄却するか」を 1 つの判定条件として文章化し、git commit で凍結してから**実行しています。

先に断っておくと、これは記事著者個人への批判ではありません。日本語圏で最も複製されている「price-level を目的変数にした LSTM 株価予測」という**型そのものの方法論検証**です。同型の指摘は Qiita 内にも既にあります。また本記事は投資助言ではなく、いかなる売買の推奨も含みません。

## 方法: Public Kill Ledger

私は [falsify-ledger](https://github.com/trow126/falsify-ledger) という公開の検証台帳を運用しています。ルールは次のとおりです。

1. 公開されている定量的な主張（論文・記事・バックテスト）を 1 つ選ぶ
2. **結果を見る前に**、主張の引用・検証手順・**唯一の primary kill condition**（何が出たら KILL か）・自分の予測確率 P(kill) を書いて git commit する（commit timestamp が事前登録の証拠）
3. 時間上限・現金コスト 0 円・無料公開データのみで検証を実行する
4. 結果がどうであれ、再現スクリプトとログごと公開する
5. 自分の予測を Brier score で自己採点する（外れも記録に残る）

重要なのは、この設計は **KILL も SURVIVE も出る**ことです。すべてを殺す台帳はただのマーケティングですが、較正された台帳は測定器になります。実際、初回 3 件の判定は KILL / KILL / SURVIVE でした（3 件目の Concretum の VIX 戦略は「通ると予測して、実際に通った」ケースです）。

今回の Entry 02 で凍結した判定条件は 1 つだけです。

> 記事のコードを同一データ・同一分割で再現し、テスト期間の RMSE を「前日終値をそのまま予測値とするナイーブ予測」と比較する。
> **KILL**: RMSE_naive ≤ RMSE_model × 1.05（ナイーブが同等以下）
> **SURVIVE**: RMSE_model < RMSE_naive × 0.80（ナイーブを 20% 以上明確に上回る）

事前予測は P(kill) = 0.95 で登録しました。

## 結果: ナイーブ予測が 42% 勝つ

記事のコードを、モデル・分割・前処理・評価ロジックに一切手を入れずに再現しました（新しい yfinance の仕様差を吸収する機械的修正のみ。全修正は公開ログに記載）。テスト期間 630 営業日、価格スケール（円）での RMSE は次のとおりです。

| 予測器 | テスト RMSE（円） |
|---|---|
| 記事の LSTM（再現実行） | **2123.49** |
| 前日終値をコピーするだけ | **1231.02** |

判定は機械的に **KILL**。前日の終値をそのまま「明日の予測」とするだけのナイーブ予測が、2 層 LSTM に **42% の大差で勝ちます**。記事は seed 未設定・epochs=1 のため実行ごとに揺れますが、seed 0 / 7 / 42 のすべてで KILL でした（LSTM 側は 2123〜3373 円の範囲で揺れ、いずれもナイーブに負けます）。

つまり「予測曲線が実線とほぼ重なる」チャートの正体は、**モデルが前日の値をほぼコピーして出力しているから 1 日遅れで重なって見える**という錯視です。しかも本件では、そのコピー戦略にすら大きく劣っていました。

### 副次的な観察（判定には使っていません）

- **MinMaxScaler の leakage あり**: scaler を全期間で fit しているため、テスト期間の高値（max=57490 円。訓練期間のみなら 35600 円）が訓練時のスケーリングに漏れています。ただし今回の KILL はこの leakage を記事のまま残した状態で成立しており、修正すればモデルはさらに不利になる方向です。
- **売買シグナル化しても価値なし**: 「予測 > 前日終値なら翌日買い」に変換すると、テスト期間 630 日中 544 日ロングで、取引コスト前の累積リターン +14.08%。同期間の buy&hold は +21.98%。**コストを引く前ですら** buy&hold に劣後します。

## なぜこの誤りが量産されるのか

これは書いた人の腕の問題ではなく、問題設定の構造の問題です。

株価の price-level（終値そのもの）はランダムウォークに近く、時点 t+1 の値の最良の単純推定は「時点 t の値」です。この目的変数で MSE を最小化するよう学習させると、**「直近の入力値をほぼそのまま出力する」関数が loss の谷になります**。LSTM は非線形関数近似器としてこの lag-copy 解を容易に表現でき、しかもそこに落ちるのが最も簡単なので、学習は素直にそこへ向かいます。

結果として:

- チャートは実線に 1 日遅れで吸い付き、「高精度」に見える
- RMSE の絶対値も一見小さく出る
- しかし前日コピーという自明な baseline と比べた瞬間、上乗せ価値がゼロ以下だと判明する

「見た目の一致」と「予測能力」を分離できる唯一の道具が baseline 比較であり、それを省いた price-level 回帰の記事は、型として同じ結論に到達します。だからこそ量産されるのです。

## 自分で確かめる方法

検証の全成果物は公開しています: [falsify-ledger の verification/02/](https://github.com/trow126/falsify-ledger/tree/main/verification/02)

- `reproduce.py` — 再現＋ナイーブ比較＋判定を行う単一スクリプト
- `data_6920T.csv` — 使用データの snapshot（yfinance は仕様が変わるため固定）
- `run_log.txt` / `seed_robustness.txt` — 実行ログと seed 追試
- 事前登録本体は `entries/02-qiita-lstm-stock-prediction.md`（凍結済み、commit timestamp 付き）

実践的な教訓は 1 行です。

> 「LSTM で株価予測」記事を読んだら、まず **前日終値コピーの RMSE と比べられているか**を確認する。比べられていなければ、そのチャートは何も示していない可能性が高い。

自分のコードに 3 行足すだけで検証できます。

```python
naive_pred = y_true[:-1]          # 前日の値をそのまま予測とする
rmse_naive = np.sqrt(np.mean((y_true[1:] - naive_pred) ** 2))
print(rmse_model, rmse_naive)     # モデルがこれに勝てないなら予測できていない
```
